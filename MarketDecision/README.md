MarketDecision is a local-first macOS SwiftUI application. The deployment target is macOS 15.0. Phase 0 is approved; Phase 1 has a limited research-scope exit decision, with its original full acceptance deferred rather than passed. Phase 2 begins with a local ledger candidate; its exit gate remains open. The application retains its synthetic DEMO workspace, separate fixed-excerpt research and explicit SEC import. There is no qualified investment-analysis workflow.

This local candidate adds an explicit AI web-search reference for S&P 500 price return to investment sharing. The predecessor `06deab7` passed hosted CI (1960 executed Swift tests, 21 native cases, Debug/Release); the citation-URL compatibility fix and its new regressions require their own exact-head CI. ## Current implementation

- SwiftUI DEMO workspace and credential settings, version-bound confirmations, closed security events and injected runtime dependencies.
- Exact decimal arithmetic, immutable model/parameter references, provenance, capability/rights/request acceptance and explicit PIT availability rules.
- SQLite source bytes, typed records, immutable research snapshots, transactional migrations and local restore/deletion plans. Research backups use the bounded ZIP profile described below; this is not crash/performance qualification.
- Candidate calendar/events and SEC adapters, core financial normalization, and a candidate stock quote/daily-bar adapter. Adapters are exercised with synthetic HTTP responses and are not installed in the application startup path.
- Explicit one-page SEC/IEX acquisition pipelines pin the SQLite revision before dispatch, accept the exact capability/rights/request response, then atomically persist source bytes and typed records. An offline evidence reader verifies stored source bytes, preserves the exact requested cutoff for replay, selects financial fact revisions without rounding the query into the future and inventories raw daily bars. It reports missing or unqualified inputs and never produces a valuation or grants analysis permission; neither pipeline is installed in the application startup path.

SEC record JSON now retains each Date as exact Foundation reference-date seconds. Availability millisecond indexes are only candidate filters: all five SEC read paths validate index/evidence consistency and apply the original cutoff to decoded evidence before selecting versions. For legacy ISO millisecond JSON, lost precision cannot be recovered: instant/interval upper availability bounds are conservatively advanced to the next canonical millisecond, without rewriting stored bytes or shifting source times, interval lower bounds or date-only evidence. Legacy normalization artifacts that no longer satisfy their source bounds require explicit recomputation. Repeated source content remains immutable and idempotent across the two date representations; raw-document retrieval metadata is not standalone PIT evidence.

The IEX stock slice explicitly requests USD, raw daily bars, a single exchange and no automatic symbol-history mapping. Quotes retain timestamp/quality; stale or invalid quotes are not upgraded. Daily aggregates are not official settlement marks, adjusted return series or historical fills. Historical retrieval does not provide source-vintage PIT evidence. Pagination means one page, not a complete calendar window. Credentials are injected into HTTP headers by an explicitly constructed adapter. The original stock-adapter slice introduced no Keychain or entitlement changes; the later isolated helper packaging is described below. See [stock-slice review](../reviews/phase1-equity-review.md).

## Local research export and recovery candidate

The research Backup tab exports Markdown and a non-encrypted ZIP containing only frozen **synthetic** research, user watchlist targets/notes and preserved conflict copies. Markdown includes missing states, exact input/source bytes and model references, and is not a restorable backup. ZIP contains exactly `manifest.json` and `research-state.json`, with version, counts, SHA-256 and ordinary ZIP CRC-32. This is a ZIP32 stored-entry profile following [PKWARE APPNOTE](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT), not a general ZIP importer: deflate, ZIP64, encryption, extra entries, links and undeclared paths are refused. It never extracts archive paths to disk. Limits are 2 GiB archive, 1 GiB per entry and 100,000 combined business records; with two stored entries there is no compression expansion. These caps are safety limits, not validated device capacity.

Restore first validates version/hash, the complete reference graph, frozen sources/model context and offline recomputation. It then previews an exact process-local plan. Merge retains conflicting graph versions under new namespaces without rewriting frozen bytes; existing watchlist values remain primary and differing incoming values are retained as conflict copies. Repeated merge deduplicates the same graph and conflict content. Restored editable entries receive fresh revisions so old drafts cannot become valid again. Conflict copies retain their original revision for inspection and rebackup.

Replace affects only research, watchlist and conflict collections; source caches stay in place. The separately confirmed Clear Synthetic Research Workspace operation removes that workspace's business collections and source caches; it does not touch the separate SEC or offline-excerpt databases. Both operations check the current persisted revision inside one SQLite transaction. Cancelled, stale or failed operations do not partially write; a transient failure retains its plan for retry, while process restart invalidates all pending plans. Keychain is never read/imported/deleted by this subsystem. External backups remain untouched; deletion is logical and does not promise physical disk erasure. Source cache files, settings, future ledgers and real-provider evidence are not in this v1 backup scope.

The seventh in-memory native case covers preview/cancel and explicit clear. File-panel acceptance remains incomplete; the previous three-case run failed. File-panel automation is manual-only in `.github/workflows/file-panel-acceptance.yml`, with no pull-request, push, schedule or workflow-call trigger. It is not run by Foundation CI; its absence is reported as NOT EXECUTED, not a pass. The separate `bash MarketDecision/Scripts/verify-file-panels.sh` suite must only be run after an explicit request to resume this acceptance. It uses the same production sources, package dependencies and Release compilation conditions in `local.marketdecision.file-acceptance`, with persistent SQLite and its own exact two-key signature: App Sandbox plus user-selected-file read/write. Its separate entitlement file excludes networking in both Debug and Release, and its target neither builds nor embeds any of the three network helpers; the acceptance app cannot enable the SEC import path. It has no UI-host root-read/test-service exceptions, injected memory store or credential setup. The checker requires this exact file-only set, including boolean types, and rejects network permissions. The acceptance package has no network helper and does not prove the production process boundary; new Xcode-injected privileges must fail rather than be accepted silently. The isolated identifier prevents acceptance clears from touching the user's application container. Three cases exercise real Markdown/ZIP panels, cancellation, corrupt imports, merge conflicts, replace/clear, process restart and explicit replay. The runner checks the exported archive independently with system unzip and SHA-256, compares frozen bytes and user values, and requires all three cases to pass without skips. Compilation, successful signing, runner initialization or a synthetic-host pass are not executed file-panel evidence. Run records must state the actual OS/toolchain and outcome.

Selected-file reads now own the preview session before IO begins. Leaving the page invalidates queued and in-flight file operations and old conflict-list deliveries; an already-started transaction still finishes and refreshes the shared workspace, but only its originating page session may publish its message or conflict list. Same-page transactional failures remain retryable; stale plans and abandoned failed plans are cleaned by their original ID only after commit has returned. Plan cleanup does not cancel or undo a committed transaction. A cancellation request immediately invalidates publication to the preview UI, so delayed file results cannot repopulate it, while the underlying file I/O may still be pending. The importer uses one no-follow regular-file descriptor and copies at most 2 GiB into independent bytes. Cancellation is checked between synchronous filesystem calls; it cannot interrupt a call already blocked in the filesystem. A local `file://` URL may refer to a network mount or file-provider-backed storage, and no cancellation latency bound is established for those volumes. The worker retains its descriptor and temporary security access until the call returns and cleanup runs, before the read API returns on success or failure. Final size/time checks reject observed changes but do not establish an atomic filesystem snapshot under arbitrary concurrent writes. Native panel callbacks keep their request identity after completion: cancellation overrides a failure for that same request in either callback order; duplicates and older requests cannot relabel a new operation. Cancellation has a neutral message and discards prepared export bytes. It does not retain bookmarks or a live memory mapping of the selected file.

Restore completion invalidates the research workspace's previous operation generation. The shared model blocks new research operations during commit and refreshes after success or failure; late reads/errors cannot publish old documents, saved markers or lists, or release the newer operation's busy state. SwiftUI submits the plan through that model instead of owning a separate refresh callback.

Merge still validates all current records it retains. Replace validates the incoming archive completely but previews target collection counts and the persisted revision without decoding payloads that will be discarded. This allows repair of corrupt watchlist, conflict or research payloads while preserving source caches. Unreadable schema/metadata, invalid backups and stale approvals still fail; rollback and retry apply equally to repairing a corrupt target. The preview explicitly says old payloads are not trusted and the entire named collections, including damaged records and reference rows, will be replaced.

Research writes now carry the business revision captured when the request begins. The shared UI checks its operation generation after acquiring that revision, then passes it explicitly through the storage protocol; queued delivery and asynchronous validation cannot renew it. Direct ResearchStore convenience methods pin the persisted revision synchronously before suspension. The existing SQLite transaction checks the original revision before writing. Clear/replace winning the race rejects an older save; a save winning first makes the destructive plan stale. There is no automatic retry with a fresh revision. Watchlist writes also require the pinned business revision in addition to their entry/draft revision, preventing a queued new entry from reappearing after clear. Invalid metadata fails instead of using a cached revision. An internal scheduling checkpoint used by regression tests never replaces or skips real document validation.

### SEC storage and client concurrency

Saved lists now return company/date/count summaries without decoding all document bodies. Opening validates only the selected immutable version; normalized values still require explicit replay. New versions append one JSON BLOB and a hash-bound catalog entry under the existing transaction revision check, without rewriting unrelated versions. The catalog is not a certificate that every body or mutable source cache is healthy. A corrupt selected body is rejected; another version can still be opened.

A SEC-purpose-only additive migration preserves every original PR42 graph byte. Its first list indexes legacy versions one at a time; each verified entry commits independently, and a corrupt or cancelled entry is not indexed. This first indexing can still be expensive. New JSON retains base64-encoded source Data but removes the additional FrozenObject base64 and duplicate content/object representation. Old binaries fail closed on the new migration history; no downgrade or destructive rebuild is provided.

The follow-up `sec-research.storage.v2` migration adds narrow ID/metadata indexes for both new BLOB and legacy object tables without rewriting frozen bytes, catalog entries or the business revision. Metadata queries intentionally specify these covering indexes: a primary-key lookup in a `WITHOUT ROWID` table can otherwise read the large BLOB even when SQL selects only an ID. Tests check the actual query plan and byte preservation across a populated v1 upgrade; elapsed time and RSS are observations, not pass/fail thresholds. First migration/index construction and first legacy cataloging remain distinct from steady-state list reads.

SEC and Equity imports share one nonblocking permit for a local application workspace. Separate environments and cooperating application processes use the same persistent `research-import.lock` inode, protected by an OS advisory lock. The permit is acquired before SEC transport construction or Equity secret access; an occupied workspace rejects the attempt without queuing. Cancellation retains ownership until the original operation and client close return. Normal owner release explicitly unlocks before closing the descriptor, so an inherited duplicate cannot retain a completed operation’s lock. Descriptors are close-on-exec; process death releases kernel ownership when its open descriptions close. The lock file is never removed, and no PID or elapsed-time rule forces an unlock. Invalid or unavailable lock files fail closed. In-memory environments use an isolated in-process permit. This is not a lock against noncooperating programs, an IP-wide rate limiter, cross-process credential revision tracking or an acknowledgement of remote helper/URLSession cleanup. Different workspaces can import concurrently. The helper remains separately sandboxed with process-wide network-client permission, not an OS two-host firewall.

Synthetic regressions cover 25 small retained versions, targeted reads, metadata/body binding, legacy compatibility, transaction rollback/CAS, cancellation and refusal before budget-exceeding page writes. Their success does not qualify arbitrary document sizes, multi-version process memory, real SEC responses or native page behavior. Live observations, when performed, are separately identified by source/build/environment; actual file-panel automation remains disabled.

In the local private observation, one retained MSFT document contained about 151 MiB of JSON. Fresh-process list/open/replay checks were repeated with one retained version and three versions (two additional copies of the same frozen inputs, not additional downloads). After the index migration, both list runs peaked at about 16 MiB of main-process RSS, selected opens at about 820 MiB, and replays at about 870 MiB.
