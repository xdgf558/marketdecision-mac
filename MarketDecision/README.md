# Native foundation and Phase 1 data slices

MarketDecision is a local-first macOS SwiftUI application. The deployment target is macOS 15.0. Phase 0 has been approved; Phase 1 and its exit gate remain open. The application retains its synthetic DEMO workspace and adds a separate fixed-excerpt offline research page. No live market provider or qualified investment-analysis workflow is connected.

## Build and test

Open `App/MarketDecision.xcodeproj` and select `MarketDecision`. Select an installed Xcode explicitly for validation:

```sh
DEVELOPER_DIR=<selected Xcode>/Contents/Developer bash MarketDecision/Scripts/verify-ci.sh all
```

Run this from the clean public repository. It checks the tracked-file boundary, module boundaries, UTC/traceability checks, the fixed Swift test catalog, Debug/Release builds, effective demo permissions and Release diagnostic isolation. Initial resolution requires network access to the pinned GRDB 7.11.1 dependency. It does not install tools or change global xcode-select. Local development uses the user-selected Xcode 27 beta 6; hosted CI uses its separately declared toolchain. CI status must be checked for the exact commit.

The optional native interaction check is `bash MarketDecision/Scripts/verify-native-ui.sh` with the same explicit `DEVELOPER_DIR`. It uses a separate synthetic in-memory host and is not production Keychain or sandbox evidence. See [CI scope](Scripts/CI.md) and [test accounting](Validation/README.md).

## Current implementation

- SwiftUI DEMO workspace and credential settings, version-bound confirmations, closed security events and injected runtime dependencies.
- Exact decimal arithmetic, immutable model/parameter references, provenance, capability/rights/request acceptance and explicit PIT availability rules.
- SQLite source bytes, typed records, immutable research snapshots, transactional migrations and local restore/deletion plans. Research backups use the bounded ZIP profile described below; this is not crash/performance qualification.
- Candidate calendar/events and SEC adapters, core financial normalization, and a candidate stock quote/daily-bar adapter. Adapters are exercised with synthetic HTTP responses and are not installed in the application startup path.
- Explicit one-page SEC/IEX acquisition pipelines pin the SQLite revision before dispatch, accept the exact capability/rights/request response, then atomically persist source bytes and typed records. An offline evidence reader verifies stored source bytes, preserves the exact requested cutoff for replay, selects financial fact revisions without rounding the query into the future and inventories raw daily bars. It reports missing or unqualified inputs and never produces a valuation or grants analysis permission; neither pipeline is installed in the application startup path.

SEC record JSON now retains each Date as exact Foundation reference-date seconds. Availability millisecond indexes are only candidate filters: all five SEC read paths validate index/evidence consistency and apply the original cutoff to decoded evidence before selecting versions. For legacy ISO millisecond JSON, lost precision cannot be recovered: instant/interval upper availability bounds are conservatively advanced to the next canonical millisecond, without rewriting stored bytes or shifting source times, interval lower bounds or date-only evidence. Legacy normalization artifacts that no longer satisfy their source bounds require explicit recomputation. Repeated source content remains immutable and idempotent across the two date representations; raw-document retrieval metadata is not standalone PIT evidence.

The IEX stock slice explicitly requests USD, raw daily bars, a single exchange and no automatic symbol-history mapping. Quotes retain timestamp/quality; stale or invalid quotes are not upgraded. Daily aggregates are not official settlement marks, adjusted return series or historical fills. Historical retrieval does not provide source-vintage PIT evidence. Pagination means one page, not a complete calendar window. Credentials are injected into HTTP headers by an explicitly constructed adapter; this batch neither requests real credentials nor changes Keychain or production entitlements. See [stock-slice review](../reviews/phase1-equity-review.md).

## Evidence boundaries

The fixed catalog records actual executions and the separately skipped real Keychain test. A skip is **NOT EXECUTED**, never a pass. Synthetic provider and SQLite tests do not qualify a vendor, feed, license, model or financial result. Original complete acceptance scenarios, full source documents and private evidence remain local. The bounded issuer fact excerpts described below have public source URLs and content hashes. The application uses a separate runtime resource containing those reviewed inputs without the test-answer fields.

The demo's production signature enables App Sandbox and user-selected-file read/write for the native research import/export panels. It grants no network-client, arbitrary-path, Downloads-folder or security-scoped-bookmark entitlement; the application does not persist selected-file access. Optional account-signed Keychain checks are described in [KeychainHost](Tests/KeychainHost/README.md). Complete accessibility/IME, real Keychain lifecycle, Intel runtime, performance and notarized distribution remain tracked limitations. Ad-hoc Debug/Release builds and synthetic UI hosts do not close them.

Data is free-first. Route B is selected, G5 remains open and no supplier is qualified. GPT does not supply missing market data. The uncomposed URLSession candidate now requires exact HTTPS hosts, disables cookies/cache and rejects redirects. Its reference owner provides an explicit idempotent close, cancels pending work on close and invalidates the delegate-bearing session when the final owner is released; its body-size check is not a streaming memory limit. Before a live adapter is composed, account/license evidence, real transport behavior, credential handling and production permissions still require review. No paid API, purchase, trading or real network data collection is part of this slice.

All rights to original project code remain reserved; dependency licenses are documented separately.

## Local research export and recovery candidate

The research Backup tab exports Markdown and a non-encrypted ZIP containing only frozen **synthetic** research, user watchlist targets/notes and preserved conflict copies. Markdown includes missing states, exact input/source bytes and model references, and is not a restorable backup. ZIP contains exactly `manifest.json` and `research-state.json`, with version, counts, SHA-256 and ordinary ZIP CRC-32. This is a ZIP32 stored-entry profile following [PKWARE APPNOTE](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT), not a general ZIP importer: deflate, ZIP64, encryption, extra entries, links and undeclared paths are refused. It never extracts archive paths to disk. Limits are 2 GiB archive, 1 GiB per entry and 100,000 combined business records; with two stored entries there is no compression expansion. These caps are safety limits, not validated device capacity.

Restore first validates version/hash, the complete reference graph, frozen sources/model context and offline recomputation. It then previews an exact process-local plan. Merge retains conflicting graph versions under new namespaces without rewriting frozen bytes; existing watchlist values remain primary and differing incoming values are retained as conflict copies. Repeated merge deduplicates the same graph and conflict content. Restored editable entries receive fresh revisions so old drafts cannot become valid again. Conflict copies retain their original revision for inspection and rebackup.

Replace affects only research, watchlist and conflict collections; source caches stay in place. The separately confirmed Clear Business operation removes all current business collections and source caches. Both operations check the current persisted revision inside one SQLite transaction. Cancelled, stale or failed operations do not partially write; a transient failure retains its plan for retry, while process restart invalidates all pending plans. Keychain is never read/imported/deleted by this subsystem. External backups remain untouched; deletion is logical and does not promise physical disk erasure. Source cache files, settings, future ledgers and real-provider evidence are not in this v1 backup scope.

The seventh in-memory native case covers preview/cancel and explicit clear. File-panel acceptance remains incomplete; the previous three-case run failed. File-panel automation is manual-only in `.github/workflows/file-panel-acceptance.yml`, with no pull-request, push, schedule or workflow-call trigger. It is not run by Foundation CI; its absence is reported as NOT EXECUTED, not a pass. The separate `bash MarketDecision/Scripts/verify-file-panels.sh` suite must only be run after an explicit request to resume this acceptance. It uses the same production sources and Release settings in `local.marketdecision.file-acceptance`, with persistent SQLite and exactly App Sandbox plus user-selected-file read/write. It has no UI-host root-read/test-service exceptions, network entitlement, injected memory store or credential setup. The isolated identifier prevents acceptance clears from touching the user's application container. Three cases exercise real Markdown/ZIP panels, cancellation, corrupt imports, merge conflicts, replace/clear, process restart and explicit replay. The runner checks the exported archive independently with system unzip and SHA-256, compares frozen bytes and user values, and requires all three cases to pass without skips. Compilation, successful signing, runner initialization or a synthetic-host pass are not executed file-panel evidence. Run records must state the actual OS/toolchain and outcome.

Selected-file reads now own the preview session before IO begins. Leaving the page invalidates queued and in-flight file operations and old conflict-list deliveries; an already-started transaction still finishes and refreshes the shared workspace, but only its originating page session may publish its message or conflict list. Same-page transactional failures remain retryable; stale plans and abandoned failed plans are cleaned by their original ID only after commit has returned. Plan cleanup does not cancel or undo a committed transaction. A cancellation request immediately invalidates publication to the preview UI, so delayed file results cannot repopulate it, while the underlying file I/O may still be pending. The importer uses one no-follow regular-file descriptor and copies at most 2 GiB into independent bytes. Cancellation is checked between synchronous filesystem calls; it cannot interrupt a call already blocked in the filesystem. A local `file://` URL may refer to a network mount or file-provider-backed storage, and no cancellation latency bound is established for those volumes. The worker retains its descriptor and temporary security access until the call returns and cleanup runs, before the read API returns on success or failure. Final size/time checks reject observed changes but do not establish an atomic filesystem snapshot under arbitrary concurrent writes. Native panel callbacks keep their request identity after completion: cancellation overrides a failure for that same request in either callback order; duplicates and older requests cannot relabel a new operation. Cancellation has a neutral message and discards prepared export bytes. It does not retain bookmarks or a live memory mapping of the selected file.

Restore completion invalidates the research workspace's previous operation generation. The shared model blocks new research operations during commit and refreshes after success or failure; late reads/errors cannot publish old documents, saved markers or lists, or release the newer operation's busy state. SwiftUI submits the plan through that model instead of owning a separate refresh callback.

Merge still validates all current records it retains. Replace validates the incoming archive completely but previews target collection counts and the persisted revision without decoding payloads that will be discarded. This allows repair of corrupt watchlist, conflict or research payloads while preserving source caches. Unreadable schema/metadata, invalid backups and stale approvals still fail; rollback and retry apply equally to repairing a corrupt target. The preview explicitly says old payloads are not trusted and the entire named collections, including damaged records and reference rows, will be replaced.

Research writes now carry the business revision captured when the request begins. The shared UI checks its operation generation after acquiring that revision, then passes it explicitly through the storage protocol; queued delivery and asynchronous validation cannot renew it. Direct ResearchStore convenience methods pin the persisted revision synchronously before suspension. The existing SQLite transaction checks the original revision before writing. Clear/replace winning the race rejects an older save; a save winning first makes the destructive plan stale. There is no automatic retry with a fresh revision. Watchlist writes also require the pinned business revision in addition to their entry/draft revision, preventing a queued new entry from reappearing after clear. Invalid metadata fails instead of using a cached revision. An internal scheduling checkpoint used by regression tests never replaces or skips real document validation.


## Fixed issuer QA and versioned growth candidate

The test bundle contains factual annual excerpts for AAPL, MSFT, META, AMZN, NVDA, COST, WMT, KO, JPM and BRK.B, from FY2024 or FY2025 issuer reports. Forty field slots contain 38 values and two explicit unavailable states. Units, fiscal periods, parent-versus-consolidated income and gross cash PP&E conventions remain explicit. NVIDIA's mixed PP&E/intangibles line is not accepted as pure capex; JPM's missing capex is not zero. Annual arithmetic alone does not qualify financial-company FCF or valuation. META's source retains its unaudited earnings-release identity.

A separate MSFT FY2023/FY2024 resource binds 56 reported quarterly/YTD/annual facts to eight issuer pages. Fifty-six independently checked discrete-quarter values, 18 annual ratio/flow expectations and 22 latest-quarter/TTM growth expectations exercise quarter bridging, four-quarter aggregation, exact decimal ratios and the new growth model. Expected values were calculated separately with Python Decimal and checked against issuer tables, not generated by the Swift implementation under test. Complete source bytes and extraction/visual-check evidence remain local; the public tests consume the fixed excerpts and cannot repeat that acquisition or visual inspection.

All sources retain retrieval-only availability and grant no historical PIT, provider or feed qualification. These manually matched issuer tables are not fabricated SEC API responses, and their semantic mapping does not extend the production SEC dictionary. The ten annual cases are not ten complete TTM valuation/scoring inputs. Real EPS, diluted shares, split basis, debt/lease classification, multi-class capital and price qualification remain separate gaps.

`fundamentals-growth.v1` is a separately referenced, offline candidate using the existing parameter set. It adds quarterly revenue, operating/net income, EPS and FCF YoY/QoQ, quarterly revenue/FCF per diluted share, signed absolute changes and TTM operating-income growth. Nonpositive bases retain explicit transition labels instead of growth percentages; missing evidence remains unavailable. Quarterly EPS/share rules have synthetic boundary tests; real MSFT evidence currently covers corporate totals only. The original `fundamentals.v1` definition and calculation behavior are unchanged. New growth reports retain their full input snapshot and recompute with the exact model and parameter references. There is no production UI wiring or model-calibration acceptance.

The issuer tests also encode/decode and recompute a financial report, freeze the excerpt/report bytes in the generic SQLite snapshot graph, reopen and restore them with unchanged hashes. This is separate from the application's synthetic-only research ZIP: that exporter explicitly rejects the non-synthetic QA graph. No real-data application backup or native file-panel acceptance follows from those tests. Full issuer taxonomy/field coverage, real-company end-to-end valuation and platform/file-panel evidence remain open; this QA increment does not close Phase 1 or its exit gate.

## Financial completion and ten-issuer quarterly evidence

`fundamentals-completion.v1` shares the approved parameter reference with the existing models. It adds revenue CAGR over four/six consecutive complete fiscal years, cash-allocation amounts with explicit cash direction, and paired FCF ex-SBC quarter/TTM/per-share growth and conversion. CAGR compares an exact decimal rational using an integer root and rounds only the final root to 18 places, half-even. Missing years, nonpositive bases, noncomparable fiscal-year lengths and Decimal38 overflow stay explicit. Existing model definitions and saved reports are unchanged; no TTM per-share aggregation or nondefault debt policy is introduced.

The independent `financial-fields.us-gaap.completion.v1` dictionary extends the previous 22 exact mappings with nine tax, pretax, depreciation, debt, lease-total and gross cash-acquisition concepts. Mixed debt/lease aggregates, lease components without a total, partial stock-plan proceeds and net-of-acquired-cash acquisition amounts do not silently fill complete slots. The mappings reference the FASB 2025 definitions and do not grant issuer, provider or historical data qualification.

`issuer-completion-golden.json` expands all ten issuers to two fiscal years of quarterly/YTD evidence, with balance-sheet and directly reported EPS/share fields where available. Independent Decimal expectations cover quarterly bridges and supported TTM ratios, capital allocation and ex-SBC metrics; MSFT also has six consecutive annual revenue values for real CAGR checks. Rounded quarterly totals can differ from annual reported totals, and the fixtures preserve that distinction. Financial-company exclusions, missing class prices, incomplete debt/lease coverage, mixed capex and unqualified split basis remain explicit. Reported weighted shares are never substituted for actual outstanding shares, and annual EPS is never subtracted to invent Q4. This is bounded accounting evidence, not ten fully qualified investment analyses or broad taxonomy acceptance.

Each issuer exercises all three model reports, complete input replay, and generic SQLite freezing/reopening/restoration. The restored graph contains factual excerpts, inputs, model definitions, the shared parameters and reports; tests rebuild a fresh registry from the restored bytes and recompute. The application remains synthetic DEMO, and its research ZIP still rejects these non-synthetic QA graphs. Source acquisition and manual mapping evidence stay local; public tests reproduce the fixed computations, not the original collection or visual inspection. ## Offline issuer research archives

The programmatic `OfflineIssuerResearchDocument` and `OfflineIssuerResearchStore` preserve the fixed ten-issuer manual-excerpt profile in a separate SQLite file and a distinct ZIP profile. Unknown issuers and transformations are rejected; this is not a general PDF or iXBRL parser. The separate offline page described below uses the document and store; the App's DEMO research and native file-panel paths remain separate. A database purpose marker prevents the ordinary business and offline issuer entry points from opening each other's files; an existing unmarked business database cannot be adopted as an issuer archive. No supplier request, Keychain access, production network permission or model parameter changes are introduced.

The document retains the full excerpt bytes and their own hash, factual mapping and reported-value/scale/sign context, retrieval timestamps, selected fiscal windows, issuer/classification/split context, three exact model definitions, shared parameters, complete inputs and cached reports. Source citations contain the original PDF/HTML hashes, URLs and locators, but the original full files are not included. Excerpt-byte integrity does not authenticate the cited original or establish vendor/license rights. Embedded QA expectations remain evidence only and never feed the calculations. Local storage and backup permission are explicit and independent.

Import validates the closed format, byte hashes, ownership/reference graph and source-to-input/model consistency. Both ZIP entries and mandatory JSON members are required; missing entries are handled as errors rather than force-unwrapped, and failed preparation leaves saved research and its revision unchanged. It does not silently rerun formulas: stored results remain cached evidence until the caller explicitly recomputes with a fresh registry and compares the reports. The restore preview and approval are process-local, pinned to the original SQLite revision, and committed atomically. Repeated merge retains origin identity and avoids duplicate content; namespace conflicts preserve both versions without rewriting frozen bytes. Ordinary transaction failures remain retryable, while stale approvals are rejected.

The existing synthetic `research-backup.v1` and new `offline-issuer-research-backup.v1` reject each other's packages. The new archive contains only its issuer research graph, excluding source caches, watchlists, credentials and original full source files. Retrieval-only evidence grants no historical PIT; missing qualified prices and actual share-class capital remain unavailable after restore. This bounded offline workflow does not qualify real investment analysis, complete product backup, native file panels, Phase 1/G1 or DATA-000/G5.

## Offline excerpt workspace

The sidebar's **离线摘录** entry (Command-4) generates the existing three candidate model reports from a closed catalog of ten reviewed issuer excerpts. This is a bounded local calculation workflow, not a live company lookup. The runtime `offline-issuer-excerpts.json` is packaged independently of the test fixtures: it preserves all 1,610 reviewed facts and input evidence, while excluding expected-answer fields. `expectedClassIDs` remains because it is an input constraint, not a test oracle. Unknown tickers fail, and a clock before the excerpts' retrieval time does not get silently advanced.

The page displays exact decimal values and units, unavailable reasons, selected periods, model/parameter references, retrieval timestamps, original-source URLs/locators/hashes and a separate excerpt hash. Full source PDFs/HTML are not embedded. Source citations and successful recomputation do not establish historical PIT, qualified capital/prices, provider rights or calibrated investment analysis.

On first navigation the application lazily opens `offline-issuer.sqlite` beside its existing business database in the application container. Startup and the DEMO workspace do not depend on this file. Each page/window has independent selection, pending operations and recomputation state; reopening the same file shares persisted records only. Saves pin the original persisted revision, and a conflict does not retry on a fresh baseline. Leaving a page suppresses late presentation updates but does not claim to roll back an already-started write. A completed save followed by a failed list refresh stays saved and cannot be resubmitted as a new save.

Opening a saved document validates its frozen structure but leaves its cached numbers **not verified**. All three report panels, including their complete metric lists, hide cached indicators until an explicit replay matches. Starting another replay immediately hides the numbers again; a mismatch, failure, new document or page exit cannot retain the previous verified display. Original source facts and missing-evidence explanations remain inspectable. The explicit replay button rebuilds from frozen inputs/models without overwriting the cache. UI-generated documents permit local storage and do not grant backup permission. This page has no file import/export controls; the existing synthetic backup and clear operations do not include its separate database.

The model owns the issuer selection used by the picker and generation action. Opening a saved version synchronizes that selection; choosing a different issuer clears the previous document and replay state, and the picker is disabled while work is pending. Each saved-version button uses the complete storage address, including its namespace, so multiple versions or restored namespace copies of the same issuer remain independently identifiable.

Catalog, composition and page-model regression tests cover exact runtime inputs, separate-store reopening, wrong-purpose rejection, stale async results, save conflicts and explicit replay. The new SwiftUI view is build-checked; visual, keyboard, VoiceOver and macOS 15 interaction acceptance for this new page remain unverified. Existing synthetic native tests do not cover this page. Actual file-panel automation remains disabled pending an explicit request to resume it. This increment does not close Phase 1/G1 or DATA-000/G5.
