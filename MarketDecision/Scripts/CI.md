# Public foundation CI

The workflow runs on pull requests, pushes to main, and manual dispatch. It uses the standard `macos-15` runner and explicitly selects Xcode 16.4. Runner image revisions may change; the log records the actual Xcode, Swift, OS and architecture. This differs from local Xcode 27 beta 6 and does not change the local toolchain or release policy.

The foundation entry point explicitly runs Swift Testing with `--no-parallel` so CPU-heavy replay fixtures cannot compete with unrelated timed transport tests. Each test still creates and controls its own concurrent tasks where needed. This changes test scheduling only: the complete catalog, single event stream, required execution/skip accounting, assertions and existing time limits remain in force.

The read-only workflow checks out the clean public repository with no persisted credential, custom cache, artifacts, secrets, signing account or provisioning profile. It runs the small public source tests, four UTC tests and module boundary checks, then builds arm64 Debug and Release using ad-hoc signatures. Effective main-app permissions must be only sandbox and user-selected-file read/write (plus optional Debug/signing metadata); no main network access is allowed. Exactly two embedded services, SEC and Equity, have sandbox and outbound-client permissions, without files, keychain, inheritance or debugging privileges. All three signatures and Release images are checked. A separate synthetic temporary app containing both exact built services must demonstrate OS denial of a direct socket, malformed-request rejection over both app-private XPC routes, and independent rejection after replacing and re-signing either helper without re-sealing the outer app. It sends no valid provider request or credentials and is not new-page UI acceptance. Ad-hoc signing is not unsigned output, account signing, notarization, or Keychain qualification.

Selected-file unit tests cover bounded copies, specific growth/truncation cases and cooperative cancellation at a held post-read hook. They verify that temporary access remains held until that hook is released and that the descriptor and scope are released before the read returns. They do not establish interruption of a blocked filesystem syscall, bounded cancellation latency on network mounts or file-provider-backed storage, or an atomic file snapshot from the final size/time checks.

The Keychain integration test is explicitly disabled. The summary says NOT EXECUTED, even if all other tests pass. The workflow does not invoke the account-signed Keychain host, application diagnostic, performance, or full private acceptance suites. A separate step runs seventeen native interaction cases in an in-memory synthetic host; file-picker operations are not part of those cases. The checker requires the exact case set, zero failures/skips and the exact host entitlement set. The host uses its own sandbox-only source entitlement file, retaining the existing exact Xcode automation exception set; production user-selected-file or outbound-network access is not inherited by the synthetic host. These host exceptions never qualify production permissions. The separate `.github/workflows/file-panel-acceptance.yml` workflow has only a `workflow_dispatch` trigger and, when explicitly requested, runs three actual system-file-panel cases against an isolated Release app that compiles the exact production source and package dependency sets, uses real SQLite, and has its own exact two-key permission set (sandbox and selected-file read/write). Its separate entitlement file excludes outbound network in both Debug and Release; neither acceptance target builds or embeds either XPC service. The production main app also has no network entitlement, but its two separately sandboxed helpers own outbound access. The app is built normally, not as an Xcode UI target, to prevent injected root-read/test-service exceptions; only the independent XCTest runner is built for testing. A before/after source fingerprint and signed-binary permission check bind the result. Foundation CI does not start the actual file-panel suite and reports it as NOT EXECUTED. Its non-UI evidence-checker unit tests still check the script's early failure path without launching an app. Routine CI success is not file-panel acceptance; previous failed runs remain failed. Do not dispatch it or run the local command without a new explicit request to resume file-panel automation. Missing, duplicate, skipped or failed cases reject the report. Only the Release acceptance product shares production compilation conditions for these file checks; its package deliberately omits both helpers and does not establish production network equivalence. The target's Debug build is not Release evidence. The 30-minute job timeout and 360-second per-case allowance are ceilings, not success evidence; a timeout remains incomplete/failed even when earlier build stages passed. Export/import evidence uses only synthetic data; it does not admit real-data backups or touch the normal application container. macOS may require local user authentication to enable XCTest automation: a runner that times out before a test begins has zero executed cases, even if xcresult contains an initialization-error placeholder. The optional local command is `bash MarketDecision/Scripts/verify-file-panels.sh` with the explicit `DEVELOPER_DIR`. Phase 0, DATA-001 and private traceability are not automatically closed. CI logs are public and contain build/test output from public source; no build or log artifact is uploaded. The tracked-file guard is defense in depth, not a guarantee against arbitrary secrets in source; clean publication review remains required.

To reproduce against a clean public checkout with an explicit local Xcode path:

```sh
DEVELOPER_DIR='/path/to/Xcode.app/Contents/Developer' bash MarketDecision/Scripts/verify-ci.sh all
```

`tests` and `builds` can be run separately. The script rejects the private planning repository before build or test execution. It never requests provisioning updates or buys hosted capacity. Branch protection is not changed by this workflow; a required check must only be configured after its real run and review.

The foundation job has a 60-minute ceiling. PR54 exhausted its former 45-minute allowance after successful tests and builds consumed 40m14s; native execution was interrupted and remains incomplete for that run. All test, build, permission and native checks remain required, including the unchanged 90-second per-case allowance and the exact seventeen-case success check. Increasing the whole-job ceiling does not convert a timed-out run into a pass. The separate file-panel workflow keeps its own existing ceiling and remains unrequested. Seventeen synthetic native cases include portfolio demo/account isolation and explicit options calculation, frozen replay and draft invalidation plus opt-in local pricing assumptions, model-result replay and pricing-edit invalidation, plus explicit risk evidence and price/IV scenario replay with edit invalidation; they do not establish full visual, accessibility or performance acceptance.

The added volatility-history case calculates a synthetic daily summary, saves and reopens it, and cancels an explicit option-archive clear preview. It never opens an importer or exporter; the exact seventeen-case set remains required.

The added option-chain case explicitly loads synthetic HTTP-shaped pages, saves and reopens their frozen evidence, selects an expiry/contract and transfers a source-bound draft to the laboratory. It does not create a real transport or read credentials. New source-binding/late-result/archive tests are Swift regressions, not actual supplier or native visual evidence. The native suite requires all seventeen cases; a compiled host or a failed/initialization-only run is not a pass.

The portfolio-Greeks case explicitly computes complete and incomplete synthetic portfolios, freezes a report and reopens it through full replay. It does not mutate the ledger or execute file panels. The exact seventeen-case suite remains mandatory; build-only or initialization failure is NOT EXECUTED, never a pass.

The offline option-evidence case explicitly calculates provider IV/Greeks differences, 25-Delta volatility and historical trade grouping from synthetic inputs, saves and replays the selected report, and invalidates its display when changing the form. It does not open a file panel or use a supplier account. The exact seventeen-case check rejects skips and initialization-only runs.

The offline market-state case uses a small missing-evidence synthetic input, verifies that unavailable scores remain unavailable, saves and fully replays its snapshot, then cancels the isolated market archive clear preview. It does not open file panels or create a provider transport. The exact seventeen-case set is required for a full native-suite pass; a locally selected case is only that case’s evidence.
