# 凭据确认状态收尾审查

本 PR 基于已合并的 PR #19，审查确认状态、写入版本校验和检查后的反馈。
不改变底层 Keychain 实现、权限、LICENSE 或阶段范围。

## 本次变更

- 移除 SwiftUI 的两份确认开关；唯一业务状态为 flow.confirmation。
- 原生 NSAlert 作为显示适配器，以单个结果回调区分确认与取消/系统结束。
- 每次弹窗有独立 ID；旧响应不能取消或确认同版本下的新弹窗，确认仅消费一次。
- 适配器保留当前原生窗口引用和 ID；这不是第二份可批准操作的业务状态。
- 替换仍须 Command-R，删除仍须 Command-D；取消用 Esc，清除默认 Return 按钮。
- save/delete 必须传 expectedRevision，不再允许 nil 或省略；进入存储前检查版本和 busy。
- 检查状态明确返回成功/失败；成功仅为发起且仍可见的页清除旧提示、恢复输入焦点。
- 失败不恢复禁用输入焦点，旧会话的完成回调不改变新会话提示；删除无用焦点参数。

## 可复跑验证

```sh
DEVELOPER_DIR=/path/to/Xcode.app/Contents/Developer bash MarketDecision/Scripts/verify-ci.sh all
```

公开候选独立通过 39 项常规 Swift 测试（本轮新增 6 项）、4 项 UTC、模块边界、
arm64 Debug/Release 构建、有效权限及 Release 诊断隔离检查。
普通 Keychain 集成测试仍默认跳过，明确 NOT EXECUTED，不计为通过。
新增测试覆盖系统结束回调、重复/过期回调、同版本新确认、关闭重开、慢检查及失败检查。
这些是生产流程状态与内存存储测试，不是 NSAlert/SwiftUI 的自动化 UI 验收。

## 本机观察及限制

本机签名 Debug 中观察到：首次保存、替换 Command-R、删除 Command-D、Esc 取消及成功焦点恢复；
替换和删除框中的 Return 均未执行动作；独立设置页检查与删除路径可用。
打开另一设置页导致旧确认关闭并显示提示，再检查成功后提示消失、输入获焦。
合成测试值已删除，退出重开显示未保存。浅色前后比较未见布局回归。
上述观察仅限本机环境；完整证据留本地，不由公开脚本或托管 CI 复跑。
macOS 15 实际 UI、非按钮系统结束的原生事件矩阵、IME、VoiceOver、完整深色、Intel、
锁屏/系统重启/备份及性能仍未验收；回调契约测试不替代这些证据。

revision 仍在检查/写入开始时变化，失败也会让其他页确认失效，这是保守失效策略。
版本校验限共享模型，不是跨进程锁，也不证明调用方取得了用户确认；UI 仍负责确认流程。
关闭窗口不撤销已发起写入。合并不关闭 Phase 0 / DATA-001，不采购、不进入下一阶段。
